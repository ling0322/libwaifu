# A C API for libwaifu

Status: design, not implemented.

The macOS app talks to `waifu webui` over HTTP: it starts the program as a child, waits for it to
print its address, and polls it twice a second. This replaces that with a library the app links:
a C ABI over the Rust crate, which Swift imports directly and .NET calls through P/Invoke. The
same header serves both, and any other language that can call C.

## Shape

```
waifu/            the library (rlib), with what the C API needs moved out of `cli`
  engine.rs       Engine: one thread that holds a model and runs jobs on it -- safe Rust,
                  tested with cargo test, and what webui's worker can become later
waifu-ffi/        cdylib: extern "C" over Engine and the catalog, nothing else
  build.rs        the link flags, the Metal kernel section included
  waifu.h         generated by cbindgen
macos/            Swift: a module map over waifu.h, and ~300 lines making it async/await
dotnet/ (later)   C#: [LibraryImport] over the same library, ~300 lines making it Task-based
```

Everything with logic in it is Rust behind a safe API. `waifu-ffi` only converts: C strings to
`&str`, structs to option structs, results to borrowed C views, panics to status codes.

## What has to move out of `cli` first

The C API needs things that only build with the `cli` feature today. They move into the library,
and `cli` uses them from there. Nothing changes in behaviour, and webui's tests check that.

| from | to | what |
| --- | --- | --- |
| `cli/hub.rs`, `cli/config.rs` | `hub` | catalog, fetch with progress and stop, model directory |
| `cli/webui/worker.rs` `Model` | `image_model.rs` `ImageModel` | the dispatch enum over Sdxl, Anima, Krea2, QwenImage |
| `worker.rs` `look_at*`, `state.rs` `Chosen`, `Spoken`, `ChosenConverter` | `describe.rs` | what a model is without reading it |
| `state.rs` `Doing::fraction`, `words` | `progress.rs` | how far along, as a number and as words |
| `cli/webui/machine.rs` | `machine.rs` | processor, memory, card, accelerators |
| (new) `flint/lutil` | `lut::setLogSink`, `fl_set_log_sink` | where flint's log lines go, when not stdout |
| (new) | `log.rs` | the Rust side's lines, and the one callback both sides' lines reach |

Features after the move:

```toml
hub    = ["dep:hf-hub", "dep:ureq", "dep:toml"]       # fetching, catalog, config.toml
engine = ["hub", "dep:serde_json", "dep:image"]       # Engine, its JSON, and resizing
cli    = ["engine", "image/png", "image/jpeg", "dep:ratatui", "dep:tiny_http"]
```

`engine` takes `image` with its codecs off, for the Lanczos resize a picture to start from goes
through; the PNG and JPEG codecs stay the command line's, since the engine takes and gives
pixels.

## Constraints the API is built around

- **A model lives on one thread.** `Tensor` holds an `Rc` and the operator handles are
  thread-local per device, so a model is made, used and dropped on the thread that made it. The
  engine owns that thread; every call from outside is a message to it.
- **One model at a time.** Two on one card double the memory, and on Metal nothing can say
  beforehand whether they fit. Loading another drops the first, on the engine thread.
- **Stopping is between steps.** Pipelines take a report callback returning `ControlFlow`; a stop
  takes effect at the next report. A step, the decode and reading the weights cannot be stopped.
- **Some failures end the process.** A device missing an operator, or a memory snapshot asked of
  Metal, aborts inside flint. Nothing in the C API can turn that into an error. The log
  callback gets the line saying why, at `WAIFU_LOG_FATAL`, before the abort, so the caller can
  write it down. Running the library in a helper process instead is possible later without
  changing this API.
- **flint prints, and has nowhere else to put a line.** Its `LOG(...)` goes to stdout with
  `printf` (`flint/lutil/internal/log.cc`), and only the level can be set. A GUI app has no
  console to read, so flint gains a sink -- `lut::setLogSink`, and `fl_set_log_sink` over it --
  that the log callback is connected to. The command line keeps printing as it does now.
- **The Metal kernels are a section of the image flint is in.** flint reads
  `__TEXT,__metallib` from the Mach-O image that contains its own code. The library is therefore
  a dylib, linked by `waifu-ffi/build.rs` with `-sectcreate`, rather than a static library whose
  section would depend on how the app happens to link it.

## Conventions

- Every symbol starts with `waifu_` or `Waifu`.
- **Strings in** are UTF-8, NUL-terminated, and borrowed only for the duration of the call.
- **Buffers in** (pixels, samples) are pointer and length, also borrowed only for the call. The
  library copies what it keeps.
- **Results out** are handed to a callback as views that are valid only until the callback
  returns. The caller copies what it keeps: Swift into `Data` and `[Float]`, .NET into managed
  arrays. Nothing out needs freeing except strings returned by synchronous calls, which are
  freed with `waifu_string_free`.
- **Every callback takes `(void *user_data, const Waifu…Event *event)`**, and nothing else: what
  it is told is one struct. The event and everything it points to are valid only until the
  callback returns. Fields added to an event later go at the end; the library writes events and
  the caller only reads them, so a caller compiled against an older header reads the part it
  knows.
- **Request structs start with `struct_size`.** The caller sets it to `sizeof` the struct it was
  compiled against. Fields added later go at the end, and an older caller's request reads as
  having the defaults for them.
- **Asynchronous functions end in `_async`.** They return at once, and report through
  callbacks: `on_progress` any number of times, then `on_complete`.
- **Errors.** Synchronous calls return a `WaifuStatusCode` and leave the message in
  `waifu_last_error()`, which is per thread. Asynchronous calls fail in one of two ways:
  - **At the call**, for what can be told without running anything: a NULL, a string that is not
    UTF-8, a `struct_size` too small, a freed engine. The function returns `0` (a NULL handle
    for `waifu_modelmanager_fetch_async`) with the message in `waifu_last_error()`, and **no
    callback is ever called** -- not `on_progress`, not `on_complete`.
  - **While running**, for everything else: a download that fails, a model that cannot be read
    or cannot do what was asked, a job for a model of the wrong kind (only known when the job's
    turn comes, since a load may be queued before it), a panic. `on_complete` gets a
    `WaifuStatus` -- the code, and the message saying why -- after whatever progress there was.
- **So: a job that was given an id gets exactly one `on_complete`, and a call that returned
  `0` gets none.** `on_complete` comes after all of the job's progress, whether it succeeded, failed, was
  cancelled (`WAIFU_CANCELLED`), or its engine was freed while it waited. It is never called
  before the `_async` function has returned, so a caller's continuation or completion source is
  always in place when it arrives. The one exception is a fatal abort, which ends the process.
- **No panic crosses the boundary.** Every entry point catches unwinding: a synchronous one
  returns `WAIFU_ERR_INTERNAL` with the panic's message, and an asynchronous one hands the same
  to `on_complete`.
- **Callbacks** run on a thread of the library's, never the caller's. They must return quickly,
  and must not call back into the library, except `waifu_engine_cancel` and the `_free`
  functions on strings.
- **The log callback is the exception to "a thread of the library's":** a line is handed over on
  whichever thread wrote it, which can be the caller's own -- `waifu_engine_new` asking about the
  device, say. It must be safe to call from any thread, and must not call into the library at
  all.

## The header

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

#define WAIFU_ABI_VERSION 1
uint32_t waifu_abi_version(void);

typedef enum {
    WAIFU_OK = 0,
    WAIFU_CANCELLED = 1,
    WAIFU_ERR_INVALID_ARGUMENT = 2,  // a NULL, a string that is not UTF-8, a size out of range
    WAIFU_ERR_UNKNOWN_MODEL = 3,     // neither a published name nor a manifest that exists
    WAIFU_ERR_FETCH = 4,             // the download failed
    WAIFU_ERR_MODEL = 5,             // the model could not be read, or cannot do what was asked
    WAIFU_ERR_NOT_LOADED = 6,        // a job, with no model, or a model of the wrong kind
    WAIFU_ERR_INTERNAL = 7,          // a panic in the library: a bug
} WaifuStatusCode;

// How a job ended, as on_complete is told it.
typedef struct {
    WaifuStatusCode code;
    const char *message;     // why, when code is not WAIFU_OK; NULL when it is
} WaifuStatus;

const char *waifu_last_error(void);  // this thread's last message; valid until its next call
void waifu_string_free(char *s);

// -- logging ---------------------------------------------------------------------------------

typedef enum {
    WAIFU_LOG_DEBUG,
    WAIFU_LOG_INFO,
    WAIFU_LOG_WARNING,
    WAIFU_LOG_ERROR,
    WAIFU_LOG_FATAL,         // the last line: the process aborts when the callback returns
} WaifuLogLevel;

typedef struct {
    WaifuLogLevel level;
    const char *source;      // where it was written: "interface.cc:84" for flint, a module for Rust
    const char *message;     // the line alone, with no level or time in front of it
} WaifuLogEvent;

typedef void (*WaifuLogCallback)(void *user_data, const WaifuLogEvent *event);

// Every line the library would print -- flint's and the Rust side's -- goes to the callback
// instead, from whichever thread wrote it. NULL puts them back on the console. Set it before
// anything else: flint writes what hardware it found the first time a device is asked about.
void waifu_set_log_callback(void *user_data, WaifuLogCallback callback);

// Lines below the level are not made at all. INFO unless set.
void waifu_set_log_level(WaifuLogLevel level);

// -- the machine -----------------------------------------------------------------------------

// A JSON document; schema below. Free with waifu_string_free. NULL on failure.
char *waifu_machine_json(void);

// -- progress --------------------------------------------------------------------------------

typedef enum {
    WAIFU_STAGE_FETCHING,    // file, done/total in bytes, part/parts
    WAIFU_STAGE_READING,     // reading weights onto the device: no fraction
    WAIFU_STAGE_ENCODING,    // the prompt, or the picture img2img starts from
    WAIFU_STAGE_DRAWING,     // done/total in steps
    WAIFU_STAGE_DECODING,
    WAIFU_STAGE_LISTENING,   // a conversion reading its recordings
    WAIFU_STAGE_SAYING,      // done/total in tokens; total is an estimate and can be passed
    WAIFU_STAGE_SOUNDING,    // the vocoder
} WaifuStage;

typedef struct {
    WaifuStage stage;
    double fraction;         // 0..1 of the whole job, or -1 where nothing can say
    uint64_t done, total;    // what stage counts; 0, 0 where it counts nothing
    uint32_t part, parts;    // FETCHING only: which file of how many
    const char *file;        // FETCHING only, else NULL
    const char *words;       // "step 3 of 8", for a status line
    double seconds;          // since the job started
} WaifuProgressEvent;

typedef void (*WaifuProgressCallback)(void *user_data, const WaifuProgressEvent *event);

// How a job that makes nothing ended: a fetch, a load, an unload.
typedef struct {
    WaifuStatus status;
} WaifuCompletionEvent;

typedef void (*WaifuCompleteCallback)(void *user_data, const WaifuCompletionEvent *event);

// -- the model manager: what is published, what is here, and fetching it --------------------
//
// None of these needs an engine, or loads anything onto a device.

// JSON documents; schemas below. Free with waifu_string_free. NULL on failure.
char *waifu_modelmanager_catalog_json(void);
char *waifu_modelmanager_describe_json(const char *model);  // a published name or a manifest path

char *waifu_modelmanager_directory(void);
WaifuStatusCode waifu_modelmanager_set_directory(const char *path);  // saved to config.toml
WaifuStatusCode waifu_modelmanager_remove(const char *name);  // deletes a downloaded package

typedef struct WaifuModelFetch WaifuModelFetch;

// Starts fetching a published model on a thread of its own and returns at once. Fetching one
// already here finishes at once. Where it went is waifu_modelmanager_describe_json's to say.
WaifuModelFetch *waifu_modelmanager_fetch_async(const char *model,
                                                void *user_data,
                                                WaifuProgressCallback on_progress,
                                                WaifuCompleteCallback on_complete);
void waifu_modelmanager_fetch_cancel(WaifuModelFetch *fetch);
// After on_complete; cancels first if it has not had it.
void waifu_modelmanager_fetch_free(WaifuModelFetch *fetch);

// -- the engine ------------------------------------------------------------------------------

typedef enum {
    WAIFU_DEVICE_AUTO,
    WAIFU_DEVICE_CPU,
    WAIFU_DEVICE_METAL,
    WAIFU_DEVICE_CUDA,
    WAIFU_DEVICE_CUDA_CPU_OFFLOAD,
    WAIFU_DEVICE_VULKAN,
} WaifuDevice;

typedef struct WaifuEngine WaifuEngine;
// 0 is never a job: an _async call returns it when it refuses at the call, with the reason in
// waifu_last_error(), and then calls none of its callbacks. Any other id gets exactly one on_complete.
typedef uint64_t WaifuJob;

// Starts the engine's thread. NULL, with waifu_last_error, if the device is not available.
WaifuEngine *waifu_engine_new(WaifuDevice device);

// Stops what is running, cancels what waits (each gets on_complete with WAIFU_CANCELLED), drops the
// model and joins the thread -- which can take until the end of the step that is running.
void waifu_engine_free(WaifuEngine *engine);

// Jobs run one at a time in the order they were asked for, loads included.
void waifu_engine_cancel(WaifuEngine *engine, WaifuJob job);  // running: after this step
void waifu_engine_cancel_all(WaifuEngine *engine);

// Fetches if needed, then reads onto the device, dropping the model before. What was loaded is
// waifu_modelmanager_describe_json's to say.
WaifuJob waifu_engine_load_async(WaifuEngine *engine, const char *model,
                                 void *user_data,
                                 WaifuProgressCallback on_progress,
                                 WaifuCompleteCallback on_complete);
WaifuJob waifu_engine_unload_async(WaifuEngine *engine,
                                   void *user_data,
                                   WaifuCompleteCallback on_complete);

// -- images ----------------------------------------------------------------------------------

typedef struct {
    uint32_t width, height;
    const uint8_t *rgb;      // width * height * 3 bytes, rows top to bottom
    size_t len;
} WaifuImage;

// An image a run is given, by name. A name the prompt writes as <|name|> is an image the model
// reads as part of what it is told: "put the girl in <|girl|> into the room in <|room|>". The
// engine writes each one the way the model was taught to read it -- Qwen-Image's "Picture 1:
// <|vision_start|>...", say -- so the caller never sees that format.
//
// Two names are kept for images that are not read but drawn with, and the prompt cannot name
// them:
//   "start_from"  img2img: the run starts from this rather than noise; see strength
//   "control"     a ControlNet's condition; see control_scale
// More will be kept as models need them -- "mask", for inpainting.
typedef struct {
    const char *key;          // letters, digits and _
    const WaifuImage *image;  // any size, scaled by the engine
} WaifuImageInput;

// Refused at the call, as WAIFU_ERR_INVALID_ARGUMENT: two images with one key; a <|name|> in the
// prompt with no image by that name, or naming a kept one; an image the prompt does not name and
// whose key is not a kept one; and any other <|...|>, which the model would read as one of its
// own markers.
typedef struct {
    uint32_t struct_size;
    const char *prompt;
    const char *negative;     // words only; "" for none; ignored by a model without guidance
    const WaifuImageInput *images;  // NULL, 0 for none
    size_t image_count;
    uint32_t width, height;   // 64..2048, multiples of the model's "alignment" (16; SDXL 32)
    uint32_t steps;
    float guidance;
    uint64_t seed;            // the caller's: the same seed and settings draw the same image
    float strength;           // with "start_from": how far it walks away from it, 0..1
    float control_scale;      // with "control": how hard it holds to it
} WaifuDrawRequest;

typedef struct {
    WaifuStatus status;
    const WaifuImage *image;  // NULL unless status.code is WAIFU_OK
} WaifuImageCompletionEvent;

typedef void (*WaifuImageCompleteCallback)(void *user_data, const WaifuImageCompletionEvent *event);

WaifuJob waifu_engine_draw_async(WaifuEngine *engine, const WaifuDrawRequest *request,
                                 void *user_data,
                                 WaifuProgressCallback on_progress,
                                 WaifuImageCompleteCallback on_complete);

// -- audio -----------------------------------------------------------------------------------

// The samples, not a file: what goes in -- a recording to sound like, or to convert -- and what
// comes out. Decoding a file to this and writing this to a file are the caller's.
typedef struct {
    const float *samples;    // mono, -1..1
    size_t count;
    uint32_t rate;
} WaifuAudio;

typedef struct {
    uint32_t struct_size;
    const char *text;
    const WaifuAudio *like;  // a recording to sound like, or NULL
    float speed, temperature;
    const char *style;       // NULL or "" for the voice's own way
    uint64_t seed;
} WaifuSpeakRequest;

typedef struct {
    uint32_t struct_size;
    const WaifuAudio *source;     // what is said
    const WaifuAudio *reference;  // whose voice to say it in
    uint32_t steps;
    bool convert_style;
    uint64_t seed;
} WaifuVoiceConversionRequest;

// Shared by speak and voice_conversion: both make audio.
typedef struct {
    WaifuStatus status;
    const WaifuAudio *audio;  // NULL unless status.code is WAIFU_OK
} WaifuAudioCompletionEvent;

typedef void (*WaifuAudioCompleteCallback)(void *user_data, const WaifuAudioCompletionEvent *event);

WaifuJob waifu_engine_speak_async(WaifuEngine *engine, const WaifuSpeakRequest *request,
                                  void *user_data,
                                  WaifuProgressCallback on_progress,
                                  WaifuAudioCompleteCallback on_complete);
// Says a recording again in another voice: what is said, and how, is the source's; whose voice
// it is, the reference's.
WaifuJob waifu_engine_voice_conversion_async(WaifuEngine *engine,
                                             const WaifuVoiceConversionRequest *request,
                                             void *user_data,
                                             WaifuProgressCallback on_progress,
                                             WaifuAudioCompleteCallback on_complete);
```

Cancelled jobs get `on_complete` with `WAIFU_CANCELLED` and a NULL image or audio: there is no
half an image, and no half a recording.

**What comes back is only the image or the audio.** Everything else about a job is the caller's
already: the seed is part of the request -- a caller that wants a fresh one each time picks it,
and so knows which one it was -- the time a job took is the caller's to measure, and the line of
parameters written under a picture is made from the request the caller sent.

## The JSON documents

JSON where the shape is wide and changes as models are added -- one more field is not an ABI
change. Everything a job is made of is a struct.

`waifu_machine_json`:

```json
{ "cpu": "Apple M5 Pro", "cores": 15, "threads": 15,
  "memory": { "total": 25769803776, "used": 19327352832 },
  "gpu": { "name": "Apple M5 Pro GPU", "unified": true },
  "vram": null, "why_no_vram": null,
  "accelerators": ["metal"] }
```

`waifu_modelmanager_catalog_json` -- published models, aliases only:

```json
{ "models": [
  { "name": "sdxl:noob", "full_name": "NoobAI XL 1.1", "kind": "image",
    "cached": true, "bytes_on_disk": 6938000000, "explicit": false } ] }
```

`kind` is `image`, `speech` or `conversion`; a model that does two is listed twice.

`waifu_modelmanager_describe_json` -- the same fields webui's `/api/model` has for its `model`, `voice` or
`converter`, under one object with a `kind`:

```json
{ "kind": "image", "name": "sdxl:noob", "full_name": "NoobAI XL 1.1",
  "on_disk": true, "in_memory": false,
  "width": 832, "height": 1216, "steps": 28, "guidance": 5.0, "takes_guidance": true,
  "sampler": "Euler", "sizes": [[1024, 1024], [832, 1216]],
  "prompt": null, "avoid": null,
  "prompt_images": 0,
  "image_keys": ["start_from"],
  "why_not": { "prompt_images": "SDXL reads words only", "control": "there is no ControlNet for it" } }
```

What a model can be given an image for is said here rather than found out from a job that fails,
so that a window shows only the boxes that do something:

- `prompt_images`: how many images the prompt can name; 0 for a model that reads words only.
  Qwen-Image 2.1 reads them through Qwen3-VL's vision tower, and is 0 here until that tower is
  exported.
- `image_keys`: the kept keys it takes images under, of `"start_from"` and `"control"`.
- `why_not`: for what it cannot take, the sentence to show in its place -- what
  `no_picture_because` was for `start_from` alone.

A request that asks for more than this anyway ends with `WAIFU_ERR_MODEL` and the same sentence.

## Inside the engine

```rust
pub struct Engine {
    commands: mpsc::Sender<Command>,
    running: Arc<Mutex<Option<JobId>>>,
    stop: Arc<AtomicBool>,                // what the running job's report callback reads
    cancelled: Arc<Mutex<HashSet<JobId>>>,
    thread: Option<JoinHandle<()>>,
}

enum Command {
    Load { job: JobId, model: String, events: Box<dyn Events> },
    Draw { job: JobId, request: DrawRequest, events: Box<dyn Events<Image>> },
    Speak { .. }, VoiceConversion { .. }, Unload { .. },
    Quit,
}
```

The thread takes commands in order. A command whose job is in `cancelled` gets `on_complete(Cancelled)`
without running. Before a job starts, `stop` is cleared and `running` set; every report reads
`stop` and answers `Break` when it is set. `Engine` is `Send + Sync`; the models are not, and
never leave the thread.

`Engine` is plain Rust with closures for progress and completion, so cargo test drives it with the
`tones` voice, which holds no weights: order, cancelling queued and running jobs, exactly one
`on_complete`, dropping the engine with jobs waiting. `waifu-ffi` wraps it, and its own tests call the
`extern "C"` functions the way C would.

## Building

- `waifu-ffi` is a workspace member with `crate-type = ["cdylib"]`, named `waifu`: the library
  is `libwaifu.dylib`, `waifu.dll` or `libwaifu.so`.
- Its `build.rs` reads `$LIBWAIFU_LIB_DIR/flint_link_flags.txt` like the crate's, and passes the
  link arguments to its own link, `-sectcreate __TEXT,__metallib` among them. On macOS it also
  sets the install name to `@rpath/libwaifu.dylib`.
- cbindgen writes `waifu.h` from the `#[repr(C)]` types, so the header cannot drift from the code.
- CMake gets a `waifu-ffi` target beside `waifu-cli`, writing the library and header to `build/`.

## The wrappers

**Swift** (`macos/Sources/WaifuKit`): a module map over `waifu.h`, and

```swift
final class Engine: Sendable {
    init(device: Device) throws
    func load(_ model: String, progress: @escaping @Sendable (Progress) -> Void) async throws -> ModelInfo
    func draw(_ request: DrawRequest, progress: ...) async throws -> Image?   // nil: cancelled
    func speak(_ request: SpeakRequest, progress: ...) async throws -> Audio?
    func voiceConversion(_ request: VoiceConversionRequest, progress: ...) async throws -> Audio?
}
```

Each call is `withTaskCancellationHandler` around `withCheckedThrowingContinuation`; the context
passed as `user_data` is an `Unmanaged` box holding the continuation and the progress closure,
released in `on_complete`. Task cancellation calls `waifu_engine_cancel` for that job.

**.NET** (later): `[LibraryImport]` declarations, a `SafeHandle` for the engine, callbacks as
`[UnmanagedCallersOnly]` function pointers with a `GCHandle` as `user_data`, and each call a
`TaskCompletionSource` completed in `on_complete`, with a `CancellationToken` registered to cancel the
job. Both wrappers marshal progress to their UI thread themselves.

## What the app gives up, and takes over

- No HTTP, no child process, no polling, no watchdog for an orphaned server.
- **History is the app's.** webui kept jobs on disk in its store; the engine keeps nothing. The
  app writes each picture or clip and its parameters to Application Support itself.
- **Encoding is the app's.** The engine hands over pixels and samples; PNG and WAV are written by
  ImageIO and AVFoundation on the Mac, by whatever .NET uses elsewhere. Resizing a picture to start
  from is the engine's, so that every caller gets the same Lanczos filter webui used.
- The launch screen can now be the whole of plan 2: the catalog with sizes on disk, downloads with
  progress through `waifu_modelmanager_fetch_async`, devices from `waifu_machine_json`.

## Order of work

1. Move hub, config, the image model dispatch, describe, progress and machine out of `cli`. webui
   and the TUI use them from their new places; the fast suites pass.
2. A log sink in flint, and `log.rs` on the Rust side; with no sink set, every line still prints
   as it does today.
3. `Engine` in the library, with its tests.
4. `waifu-ffi`, cbindgen, the CMake target, and C-level tests.
5. WaifuKit in Swift, and the app moved onto it.
6. .NET, when it is wanted.

## Open questions

- In the app's process, or in an XPC service the app starts. This design assumes the first; the
  second keeps a fatal abort from taking the window with it, and changes nothing above.
- Model directory: kept as the command line's, `~/.cache/libwaifu/models`, so that the two share
  downloads, with `waifu_modelmanager_set_directory` for anyone who wants it elsewhere.
- No memory check on Metal, since flint cannot ask. On CUDA it could be one more JSON call.
