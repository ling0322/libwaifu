# How a picture was made

Status: design, not implemented.

A picture libwaifu draws is a PNG: the macOS app writes what made it to a JSON beside it, and webui
writes an A1111 `parameters` line into it, and neither says which build drew it, on what, or from
which weights.

Every picture libwaifu writes will have a record of how it was made -- which build, which model,
what was asked for and where it ran -- in a JSON file beside it. **The record describes the picture;
it does not contain everything needed to draw it again.** It can be drawn again when the model it
names and any picture it was drawn from are at hand. The record is a format libwaifu promises to
read for as long as it reads pictures, so it is written down here before any code writes it.

## The files

```
waifu-20261011-152219.png     the picture
waifu-20261011-152219.json    the record of how it was made
```

The record has the picture's name, with `.json` for `.png`, in the same folder, wherever libwaifu
writes a picture: the macOS app's output folder, webui's, and a picture saved somewhere else.

It is beside the picture rather than in it so that the picture can be handed on without it. A
prompt is the most private thing about a picture, and a record in the PNG goes wherever the PNG goes,
to people and sites its owner never meant to show the prompt to; a record beside it goes only where
it is taken. The cost is the other side of the same thing: a picture moved without its record, or
renamed apart from it, no longer says how it was made.

The PNG itself says only who made it, in two `tEXt` chunks after `IHDR`:

| Keyword    | Holds                                     |
| ---------- | ----------------------------------------- |
| `Software` | `libwaifu 0.1.0 (3cad8b6)`                |
| `Comment`  | `Generated by libwaifu, build 3cad8b6.`   |

Both are keywords the PNG specification names, which exiftool and most viewers that show text
chunks know; `tEXt` is Latin-1, so they are in English. There is no `parameters` chunk: webui's
goes.

## The record

```json
{
  "format": "libwaifu.image",
  "version": 1,
  "created": "2026-10-11T07:22:19.199Z",
  "libwaifu": {
    "version": "0.1.0",
    "revision": "3cad8b6e1f0a9d7c5b3e2f4a6c8d0e1f2a3b4c5d"
  },
  "model": {
    "name": "anima:turbo:v1.1",
    "repo": "ling0322/libwaifu-anima-turbo-v1.1",
    "revision": "9f3c2a1e5b7d4c6f8a0b2d4e6f8a0c2e4b6d8f0a"
  },
  "task": "txt2img",
  "request": {
    "prompt": "masterpiece, best quality, score_7, safe, 2girl, yuri",
    "negative": "",
    "width": 1216,
    "height": 832,
    "steps": 10,
    "guidance": 1.0,
    "seed": "15603977047213861476"
  },
  "inputs": {},
  "runtime": {
    "device": "metal",
    "kernels": "nax",
    "dtype": "f16",
    "rng": "philox4x32-10/1"
  },
  "result": { "generation_seconds": 15.53 }
}
```

`model`, `request` and `inputs` are what to draw it again from; `runtime` says where it was drawn,
which decides how close a second drawing can be expected to come.

### Top level

| Field     | Type   | Means                                                                       |
| --------- | ------ | --------------------------------------------------------------------------- |
| `format`  | string | Always `"libwaifu.image"`. A reader that finds anything else stops.         |
| `version` | int    | This document's version of the record. See [Versions](#versions).          |
| `created` | string | When the drawing finished: UTC, ISO 8601, always three digits of milliseconds and a `Z` (`2026-10-11T07:22:19.199Z`). |
| `task`    | string | `"txt2img"` or `"img2img"`.                                                 |

### `libwaifu`: which build drew it

| Field      | Type          | Means                                                                    |
| ---------- | ------------- | ------------------------------------------------------------------------ |
| `version`  | string        | The crate's version, `CARGO_PKG_VERSION`.                                |
| `revision` | string / null | The full commit it was built from, 40 hex digits; `null` without git.    |

`build.rs` stamps `WAIFU_REVISION` today as the 7-digit short hash; the record wants the full one,
which no number of later commits can make ambiguous.

The build is also what says how the request was drawn. The sampler is not in the request: it
follows from the model's family, is implemented by libwaifu, and takes its settings from the
manifest, which `model.revision` pins. So the same model drawn by two builds is drawn by the same
sampler only as far as nothing in it changed between them.

### `model`: which weights

| Field             | Type          | Means                                                            |
| ----------------- | ------------- | ---------------------------------------------------------------- |
| `name`            | string / null | The catalog name with its version, alias resolved: `anima:turbo:v1.1`, never `anima:turbo`. `null` for a manifest chosen from a file. |
| `repo`            | string / null | The hub repository it came from. `null` for a manifest from a file. |
| `revision`        | string / null | The commit of `repo` every one of its files -- the manifest and the weights -- was downloaded at. `null` when that is not known. |

**The commit is what pins the model; nothing is hashed.** The manifest is a file of the repository
like the weights, so the commit pins it too, and with it the sampler's settings in its `config`.
Manifests carry no version and no hashes, and downloads follow the hub's `main` branch, so a name
alone does not say which weights.
The hub sends the commit with every file (`X-Repo-Commit` on Hugging Face), and the download keeps it
in the cache beside the file. The cache is flat and files are fetched one at a time, so a model can
hold files fetched at two commits; `revision` is written only when every file of the model was
fetched at the same one, and is `null` otherwise -- as it is for a model fetched before commits were
kept, and for a manifest from a file. **A `null` revision means the model cannot be told apart, not
that it is the latest.** A model from a manifest of one's own has no name, no repository and no
revision, and says nothing about which model it was. A file in the cache changed by hand is not
noticed: the record says what was downloaded, not what is on the disk.

### `request`: what was asked for

The fields of `DrawRequest`, **as the engine drew with them**. The prompt is passed to the engine
exactly as it was typed -- libwaifu expands nothing in it; a `<|key|>` in it names an image of the
request and is kept as written -- and the other fields are the values after the engine has decided
them:

| Field      | Type   | Means                                                                    |
| ---------- | ------ | ------------------------------------------------------------------------ |
| `prompt`   | string | The text the engine was given.                                           |
| `negative` | string | `""` for a model that takes no guidance, which drops it.                 |
| `width`    | int    | Pixels.                                                                  |
| `height`   | int    | Pixels.                                                                  |
| `steps`    | int    |                                                                          |
| `guidance` | number | The model's own for a model that takes no guidance.                      |
| `seed`     | string | The seed drawn with, a u64 in decimal. A seed asked for as random is the one chosen. |
| `strength` | number | `img2img` only: how far from the picture, after clamping to 0..1.        |

If libwaifu ever expands a prompt -- wildcards, templates -- `prompt` stays what the engine was given,
and what was typed goes in a field of its own.

### `inputs`: what was drawn from

Empty for `txt2img`. For `img2img`:

```json
"inputs": {
  "start_from": {
    "sha256": "…",
    "source": "file",
    "width": 1024,
    "height": 1536,
    "preprocess": "libwaifu.picture/1"
  }
}
```

| Field        | Type   | Means                                                                      |
| ------------ | ------ | -------------------------------------------------------------------------- |
| `sha256`     | string | SHA-256 of the bytes hashed, which `source` says.                          |
| `source`     | string | `"file"`: the bytes of the file it was given. `"encoded"`: it came with no file -- dragged out of another app, pasted -- and these are the PNG the app encoded it to. |
| `width`      | int    | Its width once decoded and turned upright, before it was resized.          |
| `height`     | int    | Its height, the same way.                                                  |
| `preprocess` | string | What turned the bytes into what the model was given, and its version.      |

The picture is not embedded: it would double the file, and it is a picture its owner has. So a
picture drawn from another cannot be drawn again from itself alone; the hash says whether the
picture someone offers is the one, and cannot find it.

It is the hash of the bytes, not of the pixels, because the bytes are the same everywhere and the
pixels are not. **What turns them into pixels is part of the record**, because the differences are
not rounding: a decoder that turns a photograph upright by its EXIF orientation hands the model
another picture from one that does not. `libwaifu.picture/1` is libwaifu's own: it decodes the
bytes, turns them upright by their EXIF orientation, converts them to sRGB by their colour profile,
lays any transparency over white, takes 8 bits a channel and resizes to the request with Lanczos3.
For it to be one thing, the bytes go to the library and the library does all of it -- today the
macOS app decodes with AppKit and webui with the `image` crate, and that moves into the library
first. Its number changes whenever any step of it would give the model a different picture.

### `runtime`: where it was drawn

| Field         | Type          | Means                                                               |
| ------------- | ------------- | ------------------------------------------------------------------- |
| `device`      | string        | `"cpu"`, `"metal"`, `"cuda"`, `"cuda-cpu-offload"` or `"vulkan"`: the device chosen, never `"auto"`. |
| `kernels`     | string / null | Which of a backend's ways it ran, where it has more than one: on Metal `"nax"` or `"simdgroup"`. `null` where there is one. |
| `dtype`       | string        | What the model computed in: `"f16"` or `"f32"`.                     |
| `rng`         | string        | What made the starting noise, and which version of it. See below.   |
**`rng` is a contract, not only an algorithm's name**: the version pins how a seed becomes the
starting tensor, element by element.

- `philox4x32-10/1`, which Metal, CUDA and Vulkan share. Philox4x32 with 10 rounds, keyed by the
  seed's low and high words; setting the seed sets the counter to 0, and every draw moves it on by
  the blocks it took. The tensor is filled in row-major order, four elements a block: block *b* is
  Philox of the counter (*b* low, *b* high, 0, 0), each word becomes a uniform
  `w · 2^-32 + 2^-33`, and words (0, 1) and (2, 3) each become two normals by Box-Muller -- the
  radius from the first, the angle from the second, cosine then sine -- in float32, cast to the
  model's `dtype` after.
- `minstd/1`, the CPU's. Park-Miller, `x = 48271 x mod (2^31 - 1)`, started at the seed mod
  2^31 - 1. A tensor of *n* elements takes *2n* uniforms `x / (2^31 - 1)`; element *i* is
  `cos(2π u[i]) · sqrt(-2 ln u[n + i])`.

A seed starts every GPU from the same noise, and the CPU from another. A reader that knows a
contract draws it the same way whatever its own default has become.

### `result`: how it went

| Field                | Type   | Means                                                                         |
| -------------------- | ------ | ----------------------------------------------------------------------------- |
| `generation_seconds` | number | Wall-clock time from the engine taking the request to its handing the picture back: encoding the prompt, sampling, decoding the latent. Not writing the PNG. |

There is no hash of the pixels. Two drawings are not the same to the bit even on one build, one
model and one device: another chip of the same family takes other kernels, a driver reorders a sum,
and the last bit that flips in one step is a pixel that differs forty steps on.

## Drawing it again

Reading a record and drawing it again are two things. A reader that can **parse** a record shows
it, whatever it says; whether it can **draw** it is a second question, answered before drawing as
one of:

- **Unavailable**: something it needs is not at hand -- the model, a picture it was drawn from, or an
  `rng` or `preprocess` this build does not have.
- **Best effort**: everything is at hand and it will draw, but promises nothing about how close it
  comes -- the model cannot be told the same (`model.revision` is `null` on either side), it is
  another `libwaifu.version`, or the combination has not been measured.
- **Compatible**: the same `model.revision`, the same `libwaifu.version`, the same `rng` and
  `preprocess`, and a `runtime` that a test has measured to draw close to the one recorded. Even then
  it is a picture close to the one beside the record, not the same one; the composition can still
  move when small differences grow.

The sampler has no number of its own: a release of libwaifu that changes how a model family samples
-- a sigma schedule, the timestep spacing, where img2img starts -- changes `libwaifu.version`. Two
builds of one version sample alike.

"Measured" is a table the tests keep: for each model family, which pairs of `device`, `kernels` and
`dtype` draw close to each other from the same request -- by how far apart their pixels are, against
a stated threshold, in sRGB. Until a pair is in it, it is best effort.

After drawing, how close it came is measured against the picture beside the record, the same way.

## Rules

### Versions

A reader reads every version there has been. Whether a change makes a new one:

| Change                                                              | New version |
| ------------------------------------------------------------------- | ----------- |
| A field that only describes: shown, never drawn with                | No          |
| A field for drawing with, whose absence means what it meant before  | No          |
| A field for drawing with, with no such meaning to fall back on      | Yes         |
| A field that means something else, or is computed differently       | Yes         |
| A field removed or renamed                                          | Yes         |

A reader ignores a field it does not know, which is only safe because a field it would draw wrongly
without comes with a new version. An `rng` or `preprocess` whose implementation changes takes a new
number of its own rather than a new record version: the record says the same thing, of a different
algorithm.

### Values

- Integers that can pass 2^53 -- seeds -- are strings.
- `guidance` and `strength` are written as the shortest decimal that reads back to the same `f32`,
  so that drawing again asks for the same number.
- Strings are UTF-8; hashes are SHA-256, 64 lower-case hex digits.

### Reading a record

A record is anybody's -- it came with a picture from somewhere -- so a reader trusts nothing in it:

- A file larger than 1 MiB is not read.
- Text that is not UTF-8, JSON that does not parse, nests deeper than 32, or has a `format` or a
  `version` it does not know: no record.
- A record is the picture's only by its name. A reader does not take it for the picture's if there is
  no picture of that name beside it.

### Where it is made

In the library, by the engine that drew: only it knows the guidance it used, the device it chose,
the seed it drew with and what it made of the picture it was given. webui and the apps write what it
hands them.

## What it is not

- **Not proof.** Nothing is signed: anybody can write any record beside any picture, and `Software`
  says who claims to have made it, not who did.
- **Not attached.** A record is the picture's by name only: moved without it, or renamed, the
  picture has none.
- **Not private, once handed on.** A record handed on with its picture hands on its prompt, and
  everything else below that tells one person from another: the input picture's hash can be matched
  to a photograph, a build of one's own has a revision nobody else's has, and a model of one's own
  names its owner's repository. What machine drew it -- its GPU, its system -- is not recorded: it
  would draw nothing differently, and it would only help tell one person's pictures apart.

## Not covered yet

- Speech and conversions: a WAV can have a record beside it the same way, with fields of its own.
- ControlNet: the engine refuses a control picture today. When it does not, `inputs` gains
  `control` and `request` gains `control_scale`.
- The CPU's noise: moving the CPU to Philox would make a seed the same noise everywhere, and change
  every picture the CPU draws from a seed. It is its own change, made with a new `rng` number, and old
  records keep drawing with `minstd/1`.
