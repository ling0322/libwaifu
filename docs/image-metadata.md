# How a picture was made

Status: the macOS app (`waifu-app/swiftui`) writes the record, beside each picture in its output
folder, from what `waifu_version_json`, `waifu_engine_device` and the catalogue's `versioned_name`
say. The `tEXt` chunks, the library writing the record itself, and the CLI, webui and Windows app
are not implemented.

Every picture libwaifu writes gets a JSON record beside it, saying which build drew it and what it
was asked to draw. The request in it is what libwaifu needs to draw a picture close to it again.

## The files

```
waifu-20261011-152219.png     the picture
waifu-20261011-152219.json    the record
```

The record is beside the picture rather than in it, so that a picture can be handed on without its
prompt. A picture moved or renamed without its record loses it.

The PNG itself carries two `tEXt` chunks and nothing else: `Software` (`libwaifu 0.1.0 (3cad8b6)`)
and `Comment` (`Generated by libwaifu, build 3cad8b6.`). webui's A1111 `parameters` chunk goes.

## The record

```json
{
  "environment": {
    "libwaifu": {
      "version": "0.1.0",
      "revision": "3cad8b6e1f0a9d7c5b3e2f4a6c8d0e1f2a3b4c5d"
    }
  },
  "request": {
    "task": "img2img",
    "parameters": {
      "model": "anima:turbo:v1.1",
      "device": "metal",
      "prompt": "masterpiece, best quality, score_7, safe, 2girl, yuri",
      "negative": "",
      "width": 1216,
      "height": 832,
      "steps": 10,
      "guidance": 1.0,
      "seed": "15603977047213861476",
      "strength": 0.6,
      "inputs": {
        "start_from": "/Users/alice/Pictures/ref-0412.jpg"
      }
    }
  },
  "result": {
    "output": "/Users/alice/Pictures/waifu/waifu-20261011-152219.png",
    "created": "2026-10-11T07:22:19.199Z",
    "generation_seconds": 15.53
  }
}
```

### `environment`

| Field                | Type          | Means                                                         |
| -------------------- | ------------- | ------------------------------------------------------------- |
| `libwaifu.version`   | string        | The crate's version, `CARGO_PKG_VERSION`.                     |
| `libwaifu.revision`  | string / null | The full commit it was built from; `null` without git.        |

### `request`

`task` is `"txt2img"` or `"img2img"`, and says which fields `parameters` has. Every value is the
one the engine drew with, never a default or `auto`.

| Field        | Type   | Means                                                                  |
| ------------ | ------ | ---------------------------------------------------------------------- |
| `model`      | string | The catalog name with its version, alias resolved: `anima:turbo:v1.1`. |
| `device`     | string | `"cpu"`, `"metal"`, `"cuda"` or `"vulkan"`; `"cuda-cpu-offload"` in old records. |
| `prompt`     | string | The text the engine was given.                                         |
| `negative`   | string | `""` for a model that takes no guidance.                               |
| `width`      | int    | Pixels.                                                                |
| `height`     | int    | Pixels.                                                                |
| `steps`      | int    |                                                                        |
| `guidance`   | number | The model's own for a model that takes no guidance.                    |
| `seed`       | string | A u64 in decimal; the one chosen when a random seed was asked for.     |
| `strength`   | number | `img2img` only, after clamping to 0..1.                                |
| `inputs`     | object | The pictures drawn from, each an absolute path, by key.                |

`inputs.start_from` is the picture `img2img` starts from. Any other key is a picture the prompt
names as `<|key|>` and the model reads (Qwen-Image 2.1); a `txt2img` whose prompt names none has
`{}`.

### `result`

| Field                | Type   | Means                                                         |
| -------------------- | ------ | ------------------------------------------------------------- |
| `output`             | string | The absolute path the PNG was written to.                     |
| `created`            | string | When drawing finished: UTC, ISO 8601 with milliseconds.       |
| `generation_seconds` | number | From the engine taking the request to handing the picture back. |

`output` says where the picture was written, not where it is: a reader takes the PNG beside the
record as its picture.

## Drawing it again

libwaifu draws `request` again as it is. The picture comes out close to the original when
`libwaifu.version` and `device` are the same; a version or a device of its own draws from other
noise or other kernels and promises nothing. It is never the same to the bit.

Within one version, how a seed becomes noise and how an input picture becomes what the model sees
do not change; a release that changes either, or how a model samples, is a new version.

What the record does not pin, and drawing again does not notice:

- **The weights.** A model name is a promise: weights that change are published under a new version.
- **The input pictures.** A file changed, replaced or gone at its path is drawn from as it is, or
  not at all.

## Rules

- The record's layout follows `libwaifu.version`; a reader ignores fields it does not know.
- Seeds are strings: they span u64, past what a JSON number keeps in JavaScript.
- A record larger than 1 MiB, not UTF-8, or not JSON is not read. A record without a PNG of its name
  beside it belongs to no picture.
- The record is written by the library, the only part that knows what the engine drew with; webui
  and the apps write what it hands them.

## Privacy

Nothing is signed: a record says what somebody claims. A record handed on hands on its prompt and
its paths, which name the user's folders and often the user. The GPU and the system are not recorded.
