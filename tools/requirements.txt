# What the exporters need. Nothing here is needed to build or run libwaifu -- only to turn a
# checkpoint into a package.
#
#     python3 -m venv .venv
#     .venv/bin/pip install -r tools/requirements.txt
#
# The two pins are a pair: diffusers 0.31 is the last that reads SDXL with transformers 4.46, so
# neither moves without the other.
#
# What put them here no longer applies. The pin was transformers 4.x because bpe_exporter.py
# imported `bytes_to_unicode` from `transformers.models.gpt2` to rebuild CLIP's byte level
# alphabet, and 5.x removed it; that exporter is gone, and nothing now reads a vocabulary out of
# transformers at all -- `tokenizer_exporter.py` asks it for the `tokenizer.json` and stores it.
# So the pins are free to move, and moving them is its own job: the reference tensors in every
# `_test.waifupkg` were generated by this pair, and a newer diffusers is a different reference.
# Worth doing, because it is also what keeps ComfyUI out of this venv -- see the note at the end.
#
# torch is unpinned: any build that matches the machine's CUDA will do, and the exporter runs on
# the CPU anyway.
torch
diffusers==0.31.0
transformers==4.46.3
huggingface-hub==0.26.2
tokenizers==0.20.3
accelerate
safetensors
omegaconf

# ftfy is not in here, and is no longer wanted. The slow `CLIPTokenizer` runs its input through it
# before matching its pattern, so a corpus generated with it present was a different corpus from
# one generated without -- which made a pip install a thing the reference depended on. The package
# now carries CLIP's `tokenizer.json` and the corpus is written by the fast tokenizer, and the fast
# tokenizer has never run ftfy. `docs/TODO.md` has what the two still disagree on.

# Reading T5's vocabulary, which is published as a `spiece.model` and no `tokenizer.json`.
# transformers converts it to one, and needs both of these to do it: sentencepiece to read the
# file, protobuf to parse the `trainer_spec` inside it that says whether it is BPE or unigram.
# That conversion is the same one transformers would do at load time, so what the package ends up
# carrying is what the reference ran.
sentencepiece
protobuf

# ComfyUI is not in here, and must not be installed into this venv.
#
# It is the reference implementation for Anima the way diffusers is for SDXL, so
# `anima_exporter.py -test_output` needs it -- but it asks for transformers >= 4.50.3, and the pin
# above is 4.46.3 because bpe_exporter.py imports something 5.x removed. Installing ComfyUI here
# breaks the SDXL exporter.
#
# It goes in a checkout of its own, with the few modules it needs in a directory of their own:
#
#     git clone --depth 1 https://github.com/comfyanonymous/ComfyUI.git /path/to/ComfyUI
#     .venv/bin/pip install --no-deps --target /path/to/pylibs \
#         comfy-aimdo==0.5.3 comfy-kitchen==0.2.33 einops torchvision torchaudio
#
# and is reached with PYTHONPATH=/path/to/pylibs and -comfyui /path/to/ComfyUI. See
# tools/anima_comfy.py.
